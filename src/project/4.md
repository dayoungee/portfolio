# 📌Summary

### 코드 스테이츠에서 진행한 Main Project로, 지도 기반의 UI를 통해 여행 일정을 계획할 수 있고, 다녀온 여행에 대해서 일지를 작성할 수 있는 웹 서비스를 개발했습니다.

### 해당 팀은 프론트 3명, 백엔드 3명 총 6명이 구성된 팀으로 진행했습니다. 백엔드 팀에선 크게 일정, 일지, 회원 세가지 도메인으로 나누어 역할을 분담했습니다. 저는 그중 회원을 담당하여 이에 해당하는 기능들을 개발했습니다.

### 평소 부족한 개념이라 생각했던 Spring Security와 OAuth2.0, 그리고 JWT 인증 방식을 프로젝트를 통해 개념을 다질 수 있어 의미있는 프로젝트였습니다. 그리고 평소 사용해보고 싶었던 Redis를 사용해볼 수 있어 더더욱 가치 있는 프로젝트였습니다.

# 🔍Meaning

### 이전 프로젝트에서 N+1 문제를 해결하지 못한 점과 Logging이 제대로 되지 않은 점이 아쉬웠습니다. 하지만 이번 프로젝트에서는 이러한 부분을 개선하기 위해 계속 리마인드하며 리팩토링하는 과정에서 N+1 문제를 해결하고, Spring AOP를 활용하여 Logging 작업을 완성했습니다.

### N+1 문제를 해결하기 위해 Fetch 전략을 지연 로딩으로 변경하고, Batch Size를 조절하여 37개 쿼리문을 5개로 줄였습니다. JPA의 Batch Size 설정을 통해 지연 로딩 시 최대 Batch Size만큼의 Entity를 한 번에 가져올 수 있게 함으로써 쿼리문을 효과적으로 줄일 수 있었습니다.

### Logging 작업을 더 효과적으로 수행하기 위해 Spring AOP를 적용했습니다. 프론트와의 협업에서 서버의 로그를 확인할 때 클라이언트에서 어떤 요청 바디를 받았는지 확인할 수 없어서 불편했던 경험을 고려하여 개선하였습니다. Spring AOP를 활용하여 서버의 로그에 클라이언트에서 전송한 요청 헤더와 바디, 엔드포인트 정보를 추가하여 편리하게 확인할 수 있도록 하였습니다.

### 회원 가입 시 이메일을 인증해야하는 절차를 넣기로 결정하여 이메일 인증을 해주는 작업이 필요했습니다. 이런 이유로 JavaMailSender를 활용하여 메일 전송 기능을 구현했습니다. 메일을 보내는 데에 시간이 다소 소요되기 때문에 비동기로 처리했습니다. 현재, Gmail SMTP 서버를 이용하여 비밀번호 재설정, 회원가입, 일정 생성 시 메일을 보내고 있습니다. 아쉬운 점은 비용 문제로 AWS SES를 사용해보지 못했다는 점입니다.

### 토큰 인증 방식에는 토큰 탈취 위험성을 고려하여 보안에 신경을 많이 써야 한다는 점도 깨달았습니다. 보안 상의 이유로 클라이언트에서는 토큰을 Local Storage가 아닌 Java Script 변수에 담아 사용하고 있습니다. 때문에 브라우저를 닫거나 새로고침하면 보관하고 있던 Access Token은 사라지게 됩니다. 이러한 상황을 고려하여 유효한 Refresh Token으로 Access Token을 발급하는 API를 작성했습니다. Refresh Token은 Access Token의 발급 용도이기 때문에 Cookie로 보관하기로 프론트와 정책을 정했습니다. 이러한 설정에서는 XSS 공격에 대비하여 HttpOnly 옵션을 설정해주었습니다. 이외에도 보안 상의 이유로 Secure 옵션을 설정하여 안전한 전송과 보안을 보장하였습니다.

### 이번 프로젝트에서는 토큰 블랙리스트 개념을 추가했습니다. 이를 위해 로그아웃을 한 유저의 토큰이나 회원 탈퇴를 한 유저의 토큰 등 무력화 해야할 토큰의 유효기간 만큼 유효기간을 설정하여 Redis에 Set해주었습니다. Redis를 메모리 기반의 데이터 저장소로 활용하여 응답속도를 빠르게 하면서도 데이터의 유효기간을 쉽게 관리할 수 있었습니다. 또한 Redis를 활용하여 Token 뿐만 아니라 이메일 인증코드의 유효기간을 설정하여 관리했습니다.

### 프로젝트를 진행하면서 Spring Security와 OAuth2.0과 친숙해지기도 했지만, 무엇보다 이렇듯 JWT 인증 방식의 보안과 관련된 부분과 다양한 예외처리에 대해서 학습할 수 있어 뜻 깊은 프로젝트였습니다.

### 토큰 인증 방식의 보안과 관련된 작업들을 경험하고 Spring Security의 Filter Chain 기반 구조에 대해 이해할 수 있었습니다. 토큰 블랙리스트를 활용하여 토큰의 유효성을 보장하고, Redis를 메모리 기반의 데이터 저장소로 사용함으로써 보안과 응답속도에 대한 이점을 얻을 수 있었습니다. 이러한 경험들을 통해 더욱 뛰어난 보안적인 웹 서비스를 개발하는데 노력하겠습니다.
